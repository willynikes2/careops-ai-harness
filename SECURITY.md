# CareOps security model

**Synthetic demo only. This is not HIPAA-compliant software.** All seeded people, patients, payers, and policies are fictional. Do not put PHI or production credentials in demo inputs, knowledge documents, fixtures, or source control.

The model is outside the authority boundary. Requests and documents may contain hostile instructions, and model responses may invent tools or records. Server-side sessions, role policy, scoped data access, validation, and deterministic execution enforce the implemented boundaries.

## Identity, infrastructure, and audit

Passwords are bcrypt hashes. Random server-side sessions expire after eight hours. The cookie is HttpOnly and SameSite=Strict; it is Secure when `NODE_ENV=production`. There is no client-supplied role switch and no session-signing secret in the current configuration. See [src/auth/passwords.js](src/auth/passwords.js), [src/auth/sessions.js](src/auth/sessions.js), and [src/auth/routes.js](src/auth/routes.js).

The Compose configuration keeps the dedicated KB on an internal network, separate from the edge network, with an API key between CareOps and the KB. This is a configuration property of [docker-compose.yml](docker-compose.yml), not evidence that a particular deployment's network has been verified. The application trusts one proxy hop, so its exposure should match that deployment assumption.

[src/audit/audit.js](src/audit/audit.js) records audit events and per-turn traces. Reset preserves these records. API callers can read their own traces; admins can read any trace and may therefore see synthetic records and rejected model output in trace details. The application exposes no audit-delete endpoint, but the database is not an immutable or cryptographically protected audit store.

## Limits of the controls

- Public demo credentials include an admin account. Role checks demonstrate separation between accounts; they do not stop a visitor from deliberately signing in with the published admin credentials. All viewers share one synthetic world.
- Validation recognizes cited source IDs (it does not prove a cited document supports each sentence), rejects claim IDs outside the authorized facts (after folding Unicode look-alikes), and rejects money, percentages and unit-bearing quantities that appear nowhere in the facts, documents or message (simple sums/differences of the user's own figures are allowed). Unsupported *non-numeric* prose can still pass; it does not verify every assertion, prevent every prompt disclosure, or require citations in every otherwise valid answer. When the knowledge base is down, the model is told to answer only from records and the user sees a note. The prompt canary is a targeted signal, not a secret-storage mechanism.
- The Attack Lab judge and boundary checks are heuristics over a limited corpus. Model Lab is a task-specific evaluation. For measured results, see the Attack Lab / Model Lab pages; neither page establishes immunity to attack. Review failure traces as well as summaries.
- The daily budget uses completed-call accounting and can be exceeded by in-flight calls. Session limits do not amount to a global abuse limit. Model Lab's fixed scenario clock does not change the shared budget's accounting day. Use provider-side spending limits; do not treat the app budget as a billing guarantee.
- The suite covers budget exhaustion and admin-only labs, but has no dedicated rate-limit saturation test. The header test is not a full browser injection test. Readiness checks provider configuration rather than making a live provider request.
- **Dismiss** cancels a proposal on the server, and proposals expire after 30 minutes; confirming a cancelled or expired proposal writes nothing and records a security event. Confirmation also checks ownership, current permission, and domain rules.
- Refused API requests (401/403, and 404s on owned resources) are recorded as sanitized `api_access_denied` security events — method, path, actor, status, correlation id; never cookies, tokens or bodies — at most once a minute per identical probe. Failed logins are rate-limited but not individually audited.
- The Attack Lab measures prompt resistance and proposal validation; it does not exercise confirmation, so its boundary count is not evidence of execution safety on its own (confirmation ownership, cancellation and expiry have their own tests).

## Before production use

OpenRouter is a demo provider. Production use with PHI requires an approved provider under a BAA and a broader compliance program; this repository makes no compliance claim. Production work would include enterprise identity and account lifecycle controls, tenant isolation, retention and redaction for inputs/traces, managed secrets and rotation, encryption and backups, tamper-resistant audit storage, global abuse controls, reserved usage budgets, monitored dependencies, and independent security review.

Use [README.md](README.md) for test commands and [DEMO_ACCOUNTS.md](DEMO_ACCOUNTS.md) for the intentionally public credentials. Keep reproduction examples synthetic and remove credentials before sharing diagnostics.
