This manual explains Payer B claim correction and appeal rules for the CareOps synthetic billing demonstration. Payer B is fictional. Use the manual with the assigned claim record and the current denial notice. Staff should preserve a clear account of what was reviewed, what remains missing, and which action is next. A payer code is a starting point for review, not permission to invent missing claim details.

## §2.1 Incomplete Claims

Denial code **CO-16** means the claim **lacked required information**. Review the denial reason and the existing claim documentation to identify the missing information. Do not assume that every CO-16 denial has the same missing field or requires the same supporting document.

**Correct and resubmit within 60 days**. Record the correction work in the claim follow-up so the deadline and next action are clear to the staff member continuing the case. Before resubmission, check the corrected information against the supporting record. Do not fill a gap with a guessed identifier, service detail, or amount.

Choose a follow-up task that reflects the work required. A coding review is appropriate when coding information needs review; a payer call can clarify a denial notice that does not explain the missing item. Each follow-up needs a one-sentence note describing a concrete next step. Creating the task does not mean the correction has already been completed.

## §3 Appeals

Appeals must be filed within **120 days**. An appeal and a corrected resubmission are different actions. The 120-day appeal window does not extend the 60-day deadline for correcting and resubmitting an incomplete claim.

Review the claim and denial notice with the billing supervisor when deciding whether an appeal is needed. Collect the relevant records and use an **APPEAL_PREP** follow-up task to describe the preparation work. Keep the appeal explanation tied to the actual claim record and retain the supporting documentation through the billing process.

If the available record does not establish the next step, ask for the missing information before changing the claim status. A status change records progress in the workflow; it does not guarantee a payer decision or payment.
